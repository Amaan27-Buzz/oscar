# OSCAR Mobile Mobile Prompts

Use the global rules in `image-prompts/README.md`.

## OSCAR Mobile Home — present

Design OSCAR Mobile, OSCAR on Android, in its calm home state.

The first viewport should answer: is OSCAR present, does anything need attention, what meaningful work is happening, and how can the user continue naturally by voice or text?

Do not use a giant `Talk to OSCAR` button or `Type instead` choice. OSCAR is already present.

Show a small/medium blue-shell/yellow-puck presence object, one concise state, at most one meaningful background item, a subtle acoustic/Sentry status, and a low-friction text/voice affordance. Use warm cream surfaces, graphite typography, tactile native controls and intentional whitespace. Avoid bottom navigation unless truly necessary.

## OSCAR Mobile — Listening

Design the same OSCAR Mobile Home composition transforming into active conversational Listening.

The OSCAR puck should shift/focus physically; the interaction surface should expand from existing geometry rather than appear as an unrelated page. Show concise live speech feedback, immediate stop/cancel, and a truthful `Listening` state.

Do not make waveform graphics the hero. This is active STT, distinct from ordinary Sentry awareness.

## OSCAR Mobile — Sentry Aware

Design OSCAR Mobile in persistent Sentry Aware mode with no urgent issue.

Show that local acoustic/event awareness is active while conversational transcription is not. Present a calm state such as `Aware · Nothing needs attention`, one subtle environment/device cue, and compact access to mode/privacy detail.

No surveillance dashboard, CCTV aesthetic or dense sensor grid.

## OSCAR Mobile — Sentry event

Design a meaningful but non-panicked Sentry event.

Example: `Unknown speaker detected near Desk · owner away` or `Desk device still powered`.

OSCAR should become more focused, not militaristic. Present the event, confidence/source summary, one recommended action and compact controls. Keep red/orange restrained and evidence-aware.

## OSCAR Mobile — Muted

Design OSCAR Mobile when conversational listening is muted but permitted local hot/reflex commands remain active according to policy.

Make the distinction understandable without a paragraph. Show `Muted` plus a subtle secondary line such as `Local safety commands available`. Provide an obvious path to resume or disable acoustic awareness entirely.

Do not imply the microphone hardware is fully off unless that state is selected.

## OSCAR Mobile — Acoustic awareness off

Design the stronger privacy state where local acoustic processing itself is disabled.

Visually distinguish this from ordinary mute. Keep the interface calm and clear, with one action to restore awareness.

## OSCAR Mobile — Active remote task

Design OSCAR Mobile monitoring a long-running task executing on a desktop machine while the user is away.

Show only one active objective, real progress/state such as `Working` or `Verifying`, the current executor `Desktop`, and contextual controls such as inspect, pause or cancel. Avoid project-management dashboard styling.

The task should feel like it has followed the user from desktop to phone.

## OSCAR Mobile — Remote task complete

Design the verified-completion state for a remote machine task.

Show concise evidence-backed completion, result/artifact access, and an optional next action such as `Shut down Desktop` only when supported/allowed. Do not use confetti or oversized success graphics.

## OSCAR Mobile — Connection Grid

Design the mobile Connection Grid as a simple owner-control surface.

Normal view should show four compact nodes:
- OSCAR Mobile · Here
- Cloud · Healthy
- Desktop · Working / Offline
- Desk Edge · Aware

The phone is the strongest everyday owner-control surface. Provide compact actions to pause autonomy, cancel work or inspect/revoke a node, but do not turn it into network administration software.

## OSCAR Mobile — Persona

Design a compact Persona settings surface.

Offer a natural-language field plus a small set of understandable controls such as Humor, Candor, Warmth, Formality, Brevity and Initiative. Show one context rule such as `University calls → formal, no humor`.

Make it feel like shaping a character, not configuring an LLM. Truthfulness/safety should appear fixed rather than adjustable.

## OSCAR Mobile — Call handling

Design an incoming-call surface where OSCAR may act according to Personal Policy.

Show caller/context, what OSCAR is currently allowed to do, and a concise action such as `Let it ring`, `Take a message`, or `Answer` where supported. If OSCAR is already handling the call, show that clearly without pretending platform capability that may not exist.

## OSCAR Mobile — Daily capture / journal

Design a privacy-conscious Sentry Capture surface for optional daily continuity recording.

Show capture sources such as calls, messages/mail, meetings and in-person conversation as separate source classes with their actual availability. Present current mode such as `Awareness only`, `Context capture`, or `Daily journal` and separate retention controls for raw audio, transcript and summaries.

Make pause/delete/privacy immediately reachable. This must not look like covert surveillance software.

## OSCAR Mobile — degraded state

Design OSCAR Mobile while cloud coordination is unavailable but local/phone capability remains.

Show an explicit availability state such as `Local` or `Limited`, what still works, what is waiting, and a calm retry/reconnect indicator. Do not show a generic error modal.
