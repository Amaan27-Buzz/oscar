# Web / Public Surface Prompts

Use the global rules in `image-prompts/README.md`.

## Landing page hero

Design a premium desktop web landing-page hero for OSCAR, a persistent ambient intelligence spanning phone, desktop, cloud, communications and physical hardware.

Use Quietly Alive + Playful Precision: warm cream canvas, graphite typography, restrained OSCAR blue/yellow, subtle tactile industrial details and broad editorial whitespace. No glass, neon, generic AI gradients or SaaS card walls.

Composition: asymmetrical and cinematic but still product-real. A small/medium OSCAR blue-shell/yellow-puck presence object anchors the page. Show `One intelligence. Many embodiments.` through a subtle relationship between a phone, desktop window, cloud node and small Edge device.

Minimal copy. No fake testimonials, metrics or feature grid.

## How OSCAR works

Design a product page explaining OSCAR through elegant spatial storytelling rather than a dashboard.

Show a simple flow: user/environment → OSCAR → capabilities across Sunday, desktop, cloud and Edge → evidence-backed result.

Use large editorial typography, sparse diagrams, tactile linework and a few physical-looking node objects. Avoid complex architecture charts and sci-fi treatment.

## Sunday + Desktop ecosystem

Design a product-story page showing Sunday mobile and OSCAR Desktop as two embodiments of the same intelligence.

Use one phone and one desktop composition connected by shared task state. Show a task beginning on desktop and continuing on phone without a chat-transfer metaphor.

Warm premium materials, quiet cream background, restrained blue/yellow identity. No device collage or feature cards.

## Voice + Sentry

Design a web page introducing OSCAR Voice and Sentry.

The main visual must distinguish:
- Sentry aware = persistent local acoustic/event awareness;
- Listening = active conversational speech recognition;
- Muted = conversational listening disabled while permitted local reflex awareness may remain;
- Acoustic awareness off = stronger privacy state.

Use calm, precise visual language. No surveillance dashboard or waveform theatre. Show privacy boundaries clearly through simple layered states and concise copy.

## Connection Grid

Design a web product page for OSCAR Connection Grid.

Show Sunday, cloud coordinator, desktop machine and OSCAR Edge as a resilient connected mesh. Sunday is the owner control surface; desktop provides high compute; Edge preserves local reflex/safety; cloud provides rendezvous/durable coordination.

Do not make a network-admin dashboard. Use a sparse spatial composition with four beautifully designed node objects and a small state rail such as `Sunday · Here`, `Cloud · Healthy`, `Desktop · Working`, `Desk Edge · Aware`.

## Privacy / trust

Design a calm security/privacy product page for OSCAR.

Communicate local-first acoustic awareness, explicit recording/transcription retention choices, phone biometric owner controls, evidence-backed verification, local physical safety and per-node revocation.

Avoid fear-based security visuals. Use a clean editorial composition with one privacy-control object and concise layered explanations.

## Persona

Design a web page introducing OSCAR's configurable character.

Show a small Persona panel with Humor, Candor, Warmth, Formality, Brevity and Initiative, plus one natural-language instruction such as `Be drier and less chatty.`

The same OSCAR can be witty, steady, formal or playful while truthfulness and safety remain fixed. Use subtle expression/motion variations in the OSCAR puck rather than multiple mascot characters.

## Download / Get started

Design a simple get-started page for OSCAR.

Show installation/availability for Sunday, Desktop and optional Edge/Cloud in a calm product layout. Avoid pricing-table SaaS design. Present a small commissioning sequence and current platform availability honestly.

## Docs entry

Design OSCAR's docs landing page.

Use the same product language but denser and more technical: clean typography, strong search, small navigation and code/diagram snippets only where useful. No giant marketing hero.

## Provider usage / routing

Design a web/account surface for model/provider usage and routing history.

Show automatic routing mode, connected providers, masked credential slots, health, usage, latency and recent model-routing decisions. Avoid a KPI-card dashboard. Use one compact provider list, one route-history detail and progressive disclosure. Keep raw keys hidden.
