## Architecture and dependency order

One existing Harness composes Controller, Runtime, Executive, Grid, Model Router,
canonical SQLite Store/Event Archive, World Model and Policy. Native clients and
outbound Workers use authenticated enrolled sessions; they do not own a second
Core, conversation archive or scheduler. Derived memory remains rebuildable.

`D1 persistent Core → D2 authenticated Grid → accounts/capability projection →
signed native authority → existing native effects and Executive → independent
verification → native projection → integrated acceptance`.

Perception, retention and action grants remain independent. Signed standing
authority binds exact capability contracts, executor and owner sessions, account
generations, policy fingerprint, expiry and revocation epoch. Full activation
explicitly reviews enabled Ask rules; it cannot override native OS permissions,
provider consent or deterministic hardware safety. Uncertain effects retain a
durable pre-effect claim and require inspection rather than automatic replay.
